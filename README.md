# Gemini Trading Suite

Next.js application that turns trading research prompts into operating reports generated by Google Gemini. The user enters only a stock name or ticker: the backend automatically retrieves metrics from Yahoo Finance, adds Yahoo/TradingView links for verification, and always asks Gemini to blend all 12 research prompts into one integrated report. The app includes 12 workflows: strategy generation, backtesting, risk/reward, market regime, multi-factor strategy, optimization, portfolio construction, trade setup, Monte Carlo simulation, drawdown analysis, macro strategy, and alpha/edge detection.

## User flow

1. Enter a stock name or ticker.
2. Generate the report.

All 12 research prompts are always included and blended automatically. No prompt selector, capital, timeframe, risk, notes, or manual metric fields are required in the interface.

## Setup

```bash
npm install
cp .env.example .env.local
# add GEMINI_API_KEY to .env.local
npm run dev
```

Open `http://localhost:3000`.

## Deploy on Vercel

This project is a Next.js app. On Vercel, use the `Next.js` framework preset and let the output directory be handled as `.next`. If the Vercel dashboard is configured with `public` as Output Directory, remove that setting or use the `vercel.json` included in this repository.

Configure these environment variables:

```env
GEMINI_API_KEY=your_key
GEMINI_MODEL=gemini-2.5-flash
```

## Environment variables

- `GEMINI_API_KEY`: Google Gemini API key, required by the server route `/api/gemini`.
- `GEMINI_MODEL`: optional, default `gemini-2.5-flash`.

## Product notes

- The Gemini key stays server-side and is never exposed to the frontend.
- Every report must include an objective investment score from 0 to 100.
- Reports are educational research, not personalized financial advice.
- Accurate backtests require real historical data; the app retrieves market data automatically where possible and asks Gemini to state assumptions clearly.

## Automatic market data

The `/api/market-data` route accepts a stock name or ticker, resolves the symbol through Yahoo Finance, and calculates technical/fundamental metrics over up to 5 years of history: price, 1Y performance, CAGR, annualized volatility, max drawdown, SMA 50/200, RSI 14, average volume, market cap, P/E, dividend yield, average dividend payment estimate, annual dividend amount, ex-dividend/payment dates when available, beta when available, an objective 0-100 investment score, suggested buy zone, preferred buy price, stop-loss, risk percentage, sell targets, and reward/risk levels. TradingView is included as a chart-verification link, not as unofficial scraping/API access.

## Buy / Sell / Risk levels

The backend calculates educational trade levels from market data using recent support/resistance and ATR-style volatility: suggested buy zone, preferred buy price, stop-loss, percentage risk to stop, target 1, target 2, conservative target-hit probabilities, expected timeframe to target if reached, sell/trim zone, upside percentages, and reward/risk. Gemini is instructed to include these levels in every report and to say when waiting for a pullback is better than buying immediately.

Target probabilities are estimated objectively from historical target-before-stop hit rates using a same-day stop-first assumption and a conservative haircut. They are not optimistic forecasts and should be treated as rough educational probabilities, not guarantees.

## Dividend data

Dividend fields come from Yahoo Finance when available. The app shows dividend yield, forward annual dividend rate, trailing annual dividend rate, estimated average payment amount, estimated cadence, ex-dividend date, and payment date. Missing dividend fields are shown as `n/a` and should be verified against the official company investor-relations calendar.

## Target timeframes

Target timeframes are estimated from historical successful target-before-stop cases. The app reports median and average trading sessions to target and converts the median into an approximate trading-week/month horizon. If there are not enough historical successes, the timeframe is shown as `n/a` rather than forcing a forecast.
